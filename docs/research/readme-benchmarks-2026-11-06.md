## 取样与数据口径

先从 [GitHub 的 dsh-plugin topic（按 stars 排序）](https://github.com/topics/dsh-plugin?o=desc&s=stars)发现候选，再回到各仓库首页及 README 源码核对。下列 stars 是本次查询时 **GitHub 仓库页面显示的取整值**，不是精确 API 计数。浏览工具返回的是当日或近日抓取的页面；本机 GitHub API 请求未成功，因此不声称这些数据是同时刻实时快照。

取样保留有实际 DSH 插件入口的项目；不把 DeepSeek Harness 母项目、awesome 目录、通用 skill、带 DSH 适配的独立 MCP 产品和桌面客户端母仓库混进“原生插件高星榜”。样本不穷举整个市场，按下面顺序阅读不代表市场排名。TUI 正从挂载插件演进为独立入口应用，单独标注这一边界。

[第三方 ranking 页](https://getdshplugins.com/ranking)标明其样本是 2026-08-16 快照，不能直接替代本次仓库核验；市场索引适合发现候选，最终展示判断以仓库 README 为准。

## 对本项目的改版判断

以下是基于样本的设计推断，不是已经证明能提高 stars 的因果结论。

1. **先看懂，再看全。** 首屏用一句话定位与短 GIF，首次循环就让人看出真实测试失败、修复后重验、改代码使旧结论过期。完整视频承担整个操作流程。
2. **让封面说明为什么要点开。** 保持真实 DSH 界面，增加清晰的产品名、具体问题和播放提示；不要只放缩小后不可读的原始网页全屏截图。封面、GIF、视频标题使用同一叙事。
3. **安装入口前移。** 快速开始应紧接演示或在首屏提供跳转，给出安装命令、最小清单和三步操作。读者无需先读安全模型与完整命令表。
4. **把证据能力变成故事。** 视频的核心不是快速敲一串命令，而是“CSV 引号 bug → 原文失败报告 → Agent 修复 → 真实通过 → 人工项仍由人确认 → 修改代码使旧结果过期”。不能让剪辑暗示一个通过结果等于整个需求已完成。
5. **保留准确的边界。** 中英文说明均保留：确认清单与执行授权不同、人工结论仅由人确认、结果仅覆盖约定检查、运行受当前 shell 与权限规则约束。
6. **文档与演示分层。** 保留完整命令与工作原理，放在使用入门之后；源码安装、旧命令别名与技术细节可以折叠。重要限制不藏进折叠区域。

## 视频与 GIF 的实现约束

七个高星样本并不都用视频，也不能得出“高星都靠 GIF”的结论。这里选择短 GIF + 可点击封面 + 完整视频，是依据本项目需要展示连续验证过程作出的判断。

- GitHub README 的稳定基础形式是仓库内图片/GIF 与可点击的视频封面。当前已有 YouTube 链接与仓库 MP4，应保持下载入口，避免把 YouTube 作为唯一观看方式。
- 不把相对路径 MP4 文本链接当作已经内嵌的播放器，也不承诺任意 HTML `<video>` 会在 GitHub README 渲染。真正的 GitHub 上传附件与仓库文件是不同的托管路径。
- [GitHub 官方附件文档](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/attaching-files)支持 MP4/MOV/WebM，建议使用 H.264 以提高浏览器兼容性；其附件大小限制是免费计划视频 10MB、付费计划 100MB。不要把这个限制误用于 git 仓库内文件。
- GIF 要兼顾清晰与体积：只保留关键片段，稳定裁切掉无关区域，给关键结果足够停留时间；完整高清视频保留在 MP4。
- 视频可增加章节提示与字幕，但界面、命令、输出与修复过程必须来自真实录制。不要生成虚假的 DSH 界面或测试通过记录。
- 现有在线视频不会随本地 MP4 重新剪辑自动更新。若生成新版，应明确区分新版仓库视频与原版在线录屏，避免封面与目标内容错配。

## 本次不采用的做法

- 不堆未经授予的“官方推荐”“市场认证”徽章。
- 不借用其他仓库 stars、目录 stars 或母项目 stars 装饰本项目。
- 不复制其他作者的 GIF、截图、插画与视频。
- 不给短 GIF 配过量动作，不让封面遮住全部产品证据，不以纯品牌动画代替真实操作。

## 第二轮重构采纳方案

第二轮按“重新组织一个产品展示页”处理，不能只改标语、缩短首屏、换 GIF 和折叠命令表。2026-11-06 再次读取了 AgentTeams、Market、Purge 的 raw README；同时直接获取 AgentTeams 与 Purge 的 SVG 源码，并查看了 Market 的 `demo-en.png`。下面的组合是本项目的新设计，借鉴模块组织与视觉原则，不复用他人素材。

### 能具体指出出处的组合

- **AgentTeams → 分栏品牌 hero。** 其 `hero.svg` 是 1200×360 深色圆角横幅，左侧大产品名与收益句，右侧用成员与任务关系传达产品模型。本项目应建立自己的分栏 SVG：左侧 `dsh-done-check`、`Done needs evidence.`，右侧用 `FAILED → VERIFIED → STALE` 状态卡传达验收随代码变化的过程。它是概念示意，不冒充实际宿主界面。
- **AgentTeams → 收益标题与能力结果配对。** 把现有长 Highlights 改为三个独立的产品模块：真实失败报告、由你确认的验收、会过期的证据。每项各有短收益句和真实局部截图；具体机制在下面解释。
- **Market → 真实效果优先、安装紧随。** 先给动图和可读的实际状态，再放安装及第一遍操作。其截图直接展示原生界面；本项目同样保留真实 DSH 会话，不把全部演示换成漂亮的假 UI。
- **Purge → 一致的品牌包装与导航。** 其横幅使用深色渐变、居中标题和底部亮色细线，README 另有目录。借鉴颜色与节奏的统一：hero、封面、章节卡共享视觉系统，正文给一行用途明确的跳转。不要复制其大段公告或徽章数量。

### 建议的完整阅读顺序

1. **品牌横幅。** 1200×360 的分栏 SVG；产品名、收益句与验收状态概念图同屏。语言入口单独一行，徽章只保留 CI、npm、MIT 与适配范围，不把 GIF 塞在横幅内部。
2. **观看／安装／清单／命令四个入口。** 居中短导航，让来安装的用户能跳过演示。
3. **“一个 CSV bug，三种结论”。** 独立大段落，整宽约 25–30 秒 GIF。说明这是同一真实会话的剪辑，展示失败原文、修复后的结果、改代码后的过期；加一行说明人工项仍由人确认。
4. **三个产品模块。** “测试报告有原文”“验收由你确认”“旧结果不会沿用”，每个模块配一张局部截图。GitHub 中用普通图片与短段落实现，避免依赖 README 不支持的自定义 CSS。
5. **第一次验收。** 安装命令、最小有效 YAML、三条分开发送的命令、第一次成功运行后能看到的状态。源码安装链接到维护文档。
6. **完整影片。** 独立 16:9 封面、新剪辑主视频、章节与原始视频入口。封面不再复用 GIF 首帧，使用左侧问题句与右侧真实证据局部；明确播放目标是新版还是原版。
7. **信任流。** `Agent drafts → You confirm → Shell runs → Evidence recorded → Edit invalidates`，结合简单 Mermaid 或自有 SVG。用箭头让人工确认与自动执行的边界一眼可见。
8. **“如何读验收结论”画廊。** 失败、自动通过但人工待确认、人工确认后状态、过期四个真实状态各给一个小标题、截图与下一步。替代只列状态名的说明。
9. **完整清单与命令参考。** YAML 字段、`watch` 范围、强制重验、证据详情、技术详情分别在这里解决；不要重复首屏收益句。
10. **适配与边界、开发、许可证。** 保留重要边界为可见正文，开发流程与技术历史通过独立文档链接承载。

落地时进一步控制 README 的长度：横幅采用 1200×400；三项收益并排展示，真实截图放在可展开的三状态证据画廊；最小 YAML、完整命令与技术规则移到双语使用指南。首次操作中的“预览 → 用户确认 → 执行”承担主页面的流程说明，不再另加一张重复的信任流图。以下媒体数据为实际成品。

### 重新制作媒体，而非只加字幕

实际采纳的主影片为 **64 秒、8 章、1080p**，使用已有真实会话重新编排，加入中文旁白和双语字幕。影片跟随一个问题的解决过程，而不是逐条念命令：

- **0–6 秒：完成，该由什么证明？ / THE QUESTION。** 用一般性问题引入验收。原录屏没有在失败检查之前出现 Agent 宣布完成，因此不把“它说完成了”当成这段会话的事实。
- **6–14 秒：先约定，怎样才算通过。 / AGREE。** 展示清单与具体自动命令，先看清验收内容。
- **14–21 秒：确认权，在你手里。 / YOUR DECISION。** 展示用户确认，明确 Agent 与用户的权限区别。
- **21–29 秒：失败原文，就是线索。 / THE EVIDENCE。** 展示真实失败与原文报告，给结论足够阅读时间。
- **29–37 秒：修好，再真正跑一次。 / FIX + RE-CHECK。** 区分 Agent 报告修复与实际重新执行；自动检查通过后仍保留人工待确认项。
- **37–45 秒：最后一项，需要你。 / HUMAN VERDICT。** 人工项由人给出结论，不把自动通过显示成全部完成。
- **45–55 秒：旧通过，不会永久有效。 / RESULTS EXPIRE。** 代码变化后，原人工结论需要重新验证；该镜头里的两项较新自动结果仍有效，字幕不声称全部结果过期。
- **55–64 秒：每句完成，都要有证据。 / YOUR NEXT TASK。** 产品名、安装命令、仓库地址，形成明确的下一步。

GIF 实际采用 **16 秒**预览，从同一真实会话提炼关键结果，不把全部命令压进动图。封面、GIF 与主片共享视觉系统，播放按钮、时长与题目对应 **1:04 新版影片**。品牌视觉采用暖黑、暖白、琥珀与薄荷色，录屏中 DSH 本身的红绿状态色保持原样；品牌横幅与真实录屏分工清晰。

### 验收标准

- 用户应能从最终页面直接指出新增的品牌 hero、三模块展示、状态画廊和首次验收流程，而不是只看到措辞变化。
- GIF 首次播放即能看懂“失败、重验、过期”，缩放到 GitHub 正文宽度后主要结论仍可读。
- 新视频与原视频在剪辑结构、章节节奏、局部放大及结尾引导上有实质区别；输出来源仍能追溯到真实录制。
- 中英文页面的模块顺序、图片、视频入口与技术事实保持一致，且所有链接在本次提交内容中可用。
